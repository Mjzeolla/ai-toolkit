# Meeting To Actions

Extract outcomes rather than retelling the meeting. Separate confirmed decisions, proposed
ideas, assigned actions, risks, and unresolved questions. Preserve names and dates only when
the source supports them; label inferred ownership or timing for confirmation.

Write each action with one accountable owner, an observable deliverable, relevant context,
dependencies, and a due date when one was actually agreed. Merge duplicates and distinguish
a discussion topic from a commitment. Flag contradictory decisions or missing owners rather
than silently resolving them.

Use `$to-ticket` for actions that need implementation-ready tracker entries and
`$decision-interview` when a deferred decision needs structured follow-up. Do not create
calendar events, send messages, or file tickets without explicit authorization.

Return a concise summary, decisions, action table, risks, and open questions. Make the
output useful to attendees and absentees without exposing irrelevant personal remarks or
reproducing the full transcript.
