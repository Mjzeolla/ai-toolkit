# Maintain Wiki

Turn the requested knowledge into a useful wiki entry with a clear owner and retrieval path. Inspect
the wiki's README, contributor guidance, content roots, navigation metadata, route conventions,
existing related pages, and validation commands before writing. Use `$author-documentation` for
reader-oriented content and `$primary-source-research` when claims depend on current external facts.

Read [wiki content model](references/content-model.md) when choosing where a note belongs or when
changing navigation. Preserve the repository's established taxonomy when it remains coherent; do not
create a new top-level category for one page.

Before adding content, search for a canonical existing page and extend it when the new information
has the same owner. Otherwise create the narrowest useful page under the relevant language, platform,
tooling, concept, practice, playbook, glossary, or notes domain. Add a meaningful landing page and
navigation metadata when a new directory is justified. Link from the nearest parent and from directly
related pages; avoid orphan routes and reciprocal link spam.

Distinguish capture maturity:

- use an inbox or daily note for unprocessed observations;
- use an evergreen note for a durable idea without a narrower owner;
- promote verified knowledge to its language, platform, tooling, concept, or practice domain;
- put repeatable action sequences in playbooks; and
- use glossary entries for concise definitions, linking to deeper explanations when needed.

Do not leave placeholder prose, empty category pages, copied source material, fabricated experience,
or unverified commands. Do not add labels, comments, frontmatter, commit trailers, or prose announcing
that content was generated by an AI. Preserve normal authorship and repository metadata.

Run the wiki's formatter, Markdown or MDX lint, local-link and route validation, code-sample checks,
and production build when available. Run external-link checks when sources changed and network access
is permitted; report timeouts separately from broken links.

Editing the wiki does not itself authorize publication. When the user asks for a branch, commit,
push, or pull request—or the explicitly delegated terminal condition requires a pull request—use
`$raise-pull-request`. Otherwise leave reviewed, validated local changes for the user.
