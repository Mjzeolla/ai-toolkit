# Brief Mode

Lead with the outcome. Keep only information that changes understanding, action, risk, or
verification. Prefer a compact paragraph or a few bullets over sections, background, and a
chronology of work.

Do not omit required warnings, blockers, exact commands, or evidence merely to be short.
Compress explanations before removing decision-critical content. Match the user's technical
altitude and define a term only when misunderstanding would be likely.

For work completed by an agent, state what changed, whether validation passed, and any
remaining action. For a decision, state the recommendation and the most important tradeoff.
For a status update, state current state, blocker if any, and next action.

Use `$handoff-summary` when continuity for another person or agent matters more than maximum
brevity. Remain in brief mode for the current response or requested exchange; do not impose
it permanently on future conversations unless the user asks.
